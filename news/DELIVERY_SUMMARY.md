## 🚀 部署指南

### 前端部署
```bash
# 1. 构建生产版本
cd SuperNews_frontend
npm install
npm run build

# 2. 上传 dist 文件夹到 Web 服务器
# 示例：上传到 Nginx
# 将 dist/* 复制到 /usr/share/nginx/html/

# 3. 配置 Nginx 反向代理
# 将 /api 请求代理到后端服务器
location /api {
    proxy_pass http://backend-server:8080;
}
```

### 后端部署
```bash
# 1. 构建 Gateway
cd SpringCloudGateway_CanaryRelease
mvn clean package

# 2. 使用 Docker 部署
docker build -t gateway:latest .
docker-compose up -d

# 3. 或直接运行 JAR
java -jar target/gateway-1.0.0.jar
```

## 🔗 项目关联

### API 接口代理
前端通过 Vite 代理配置连接到后端：
```javascript
// vite.config.js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true
  }
}
```

### 认证流程
1. 用户在前端登录
2. 后端验证返回 token
3. 前端存储 token 到 localStorage
4. 所有 API 请求自动添加 Authorization 头
5. 后端在 Gateway 层验证 token

### 灰度发布流程
1. 新功能部署到灰度版后端
2. 配置灰度规则（指定用户、IP、流量比例等）
3. Gateway 根据规则路由用户请求
4. 灰度版本承载部分流量
5. 验证通过后全量发布

## 📞 常见问题解决

### Q: 前后端如何联调？
A: 
1. 启动 Gateway 服务（localhost:8080）
2. 启动前端开发服务器 (npm run dev)
3. 前端通过 `/api` 代理请求会自动转发到 8080
4. 在浏览器 Network 标签页查看请求

### Q: 如何添加新的灰度策略？
A:
1. 在 Gateway 项目创建新类实现 `CanaryStrategy` 接口
2. 实现 `selectCanaryVersion()` 方法
3. 在 Gateway 中注册并配置
4. 通过管理 API 动态添加规则

### Q: 如何扩展新闻模块？
A:
1. 在 `/src/api/news.js` 添加新的 API 接口函数
2. 在 `/src/stores/newsStore.js` 添加相应的状态
3. 在页面中使用新的 API 和状态
4. 添加对应的页面或更新现有页面

### Q: 缓存什么时候过期？
A:
- 新闻分类：2 小时
- 新闻详情：1 小时
- 用户信息：1 小时
- 登出时：清空所有缓存

### Q: 如何处理跨域问题？
A:
1. 前端：在 vite.config.js 配置代理
2. 后端：在 Gateway 配置 CORS headers
3. 或在实际 API 服务中配置 CORS
